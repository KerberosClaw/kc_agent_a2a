# Security reporting

See [privacy boundaries](docs/privacy.md) before using real data. This technical preview has no guaranteed response time or supported-version SLA.

Please use the repository's private vulnerability reporting channel when it is available. If it is unavailable, open an issue containing only a request for a private reporting channel, with no exploit payload, credentials, IDs, private content or logs. Do not publish sensitive evidence to get attention.

Provide a minimal fictional reproduction, affected version, OS/native CLI versions and the boundary that failed. Revoke exposed credentials with the relevant provider; removing a file from the latest commit does not remove earlier copies. Do not run history rewriting or destructive cleanup without a recovery plan and explicit maintainer coordination.
